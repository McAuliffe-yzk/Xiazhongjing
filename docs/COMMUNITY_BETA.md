# 匣中镜 Community Beta v0.4.1

## 发布目标

Community Beta 面向愿意在本地使用自己的文稿训练个人创作 Agent 的单人创作者。公开版本验证三个问题：

1. 新用户能否在 20 分钟内完成安装、真实模型验证和个人身份配置。
2. 用户能否导入自己的历史文案和任意书籍，建立可审核的个人 DNA 与精神书库。
3. 用户能否用自己选择的 DNA 与书籍完成首篇生成，并创建可用的镜中人和书中人。
4. 用户能否从个人历史、近期创作和有效书库中获得可转化、可反馈的每日灵感。

## 功能状态

| 模块 | 状态 | 边界 |
| --- | --- | --- |
| 项目、素材、文案、版本、日记 | Beta | 单用户、本地优先 |
| 个人 DNA 蒸馏与发布 | Beta | 候选版本必须人工发布 |
| 文案生成与重写 | Beta | 依赖 DeepSeek 兼容 API |
| Creator Onboarding | Beta | 七项能力按真实数据状态检查 |
| 动态精神书库 | Beta | 用户自行建书、导入资料、确认直接引文 |
| 个人记忆引擎 v1 | Beta | SQLite FTS5，无向量数据库 |
| 镜中人 | Beta | 展示依据，不展示隐藏思维链 |
| 书中人 | Beta | 用户从一本或多本已导入书籍创建，可选联网 |
| 灵感匣签 | Beta | 每日一次，成功后锁定；支持反馈、转化与发布指标 |
| 封面图 | Experimental | 依赖兼容的图片生成服务 |
| MCP | Beta | 单实例工具接口，不是多租户平台 |

## 空白安装流程

1. 运行 `python scripts/bootstrap.py --start`。
2. 打开“设置”，填写模型 API Key 并测试连接。
3. 打开“个人信息”，填写名称、定位、栏目和风格关键词。
4. 在“内容蒸馏”批量上传 DOCX、PDF、TXT 或 Markdown 历史文稿。
5. 审核候选个人 Skill，确认后发布。
6. 在“精神书库”新建书籍，导入书籍原文或阅读笔记；确认候选直接引文。
7. 从已导入书籍创建至少一位书中人。
8. 新建项目，选择允许调用的书籍，录入真实素材并生成文案。
9. 在镜中人中提问，通过“查看依据”确认系统调用了哪些历史片段。
10. 在“灵感匣签”选择今天最需要的一类签，抽取后可反馈并转入创作。

## 私人数据隔离

公开发布必须排除：

- `.env`、数据库和任何 API Key
- 真实历史文稿、项目、对话和日记
- 用户上传的 PDF、DOCX、图片与封面
- 私人书库语录语料
- 维护者正式个人 Skill 和 Profile Pack

`scripts/package_community_beta.sh` 会排除当前维护者的私人知识文件并扫描常见密钥格式。它不是完整的数据合规审计；发布前仍需人工检查 ZIP 内容和 Git 历史。

由于私人 Skill 曾在内部仓库历史中出现，公开发布应使用全新的干净仓库或 orphan 分支导入 Community Beta ZIP，不要直接公开内部仓库历史。

## 版本门槛

- `v0.4.x-beta`：至少 5 位外部创作者完成空白安装、个人 DNA、个人书库、一篇真实创作和一次灵感反馈。
- `v0.5.x-beta`：补齐页面化备份恢复、迁移回滚和错误恢复面板。
- `v1.0.0`：至少 20 位外部创作者验证，无已知数据丢失问题，Windows/macOS/Linux 安装通过，升级迁移可重复执行。

## 已知限制

- 当前是模块化单体，不支持账户系统、多人协作与云端多租户。
- SQLite 适合单用户；Web 与 MCP 并发重写同一数据库时需要控制使用频率。
- 通用书籍的无引号短句默认待人工确认；系统不会把模型常识自动写成可直接引用原句。
- 对话使用阶段事件加最终结构化结果，不做不可靠的伪 token 流式输出。
- FTS5 trigram 不可用时会回退到 unicode61 和本地确定性评分。
