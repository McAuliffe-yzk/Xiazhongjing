03 / CREATION FLOW

从生活素材到正式发布

主路径保持短而可控；思考、知识和视觉资产在需要时进入，不劫持正文创作。

  1. 01
    准备素材

    主题、开场、洞察、日常、事件、原句、收束意象。

  2. 02
    个人风格撰写

    以 v2.2 DNA 发展素材关系，建立完整叙事运动。

  3. 03
    抖音表达优化

    优化开头、口语节奏、高潮与回扣，不改成模板文。

  4. 04
    书库金句支撑

    从本地有效直引中匹配真实转念时机。

  5. 05
    人工精修

    改写只认当前编辑器正文，支持锁定、版本和长度硬约束。

  6. 06
    封面与发布

    生成栏目封面，发布到日记，并无负担记录真实采用结果。

对话是独立的思考空间

镜中人、书中人产生的内容只有在用户主动沉淀后才进入资产库；不会自动改写当前项目。

04 / EXECUTION CONTRACT

不是“按钮存在”，而是执行有约束

以下契约定义每个生成选项在真实链路中的输入、行为和失败边界。

MATERIAL BOUNDARIES

三种素材表达边界

01原句

逐字保留，仅调整位置与前后过渡。

真实对话、日期、专有表达
02 · 默认改写

保留事实和含义，按个人 DNA 重建句法与叙事关系。

绝大多数生活素材和核心事件
03阐释

先保留原句，再用当前事实或个人判断展开。

需要被听懂的重要洞察
05 / KNOWLEDGE & MEMORY

知识不是堆积，而是带质量门的个人记忆

书库只向生成提供通过质量门的直接引文；镜中人则使用压缩后的历史文稿记忆，不搬运历史事实。

06 / MODULAR MONOLITH

可演进的模块化单体

当前不拆微服务；先把页面、用例、领域服务和数据边界分清，让真实创作链路可维护、可测试、可交付。

01 · EXPERIENCEVanilla HTML / CSS / JavaScript

单页壳、领域脚本、URL 状态、加载与错误反馈

02 · APPLICATIONFastAPI Router + Use Case

generation · state · style · library · dialogue · dna · covers · settings

03 · DOMAINSkill Runtime + Domain Services

个人写作 · 书库质量 · 对话记忆 · 封面服务 · 任务检查点

04 · DATA & MODELSQLite + Local Media + Model APIs

本地优先持久化 · DeepSeek · Image API · 可选搜索增强

A失败不覆盖

字数、锁定段落或任务契约失败时保留用户当前稿。

B检查点恢复

生成任务保存输入指纹与阶段结果，重试复用已完成工作。

C密钥隔离

API Key 不进入模板、文档、Git、数据库导出和交付包。

D数据归属清楚

项目、对话、书库、封面和发布快照各自拥有明确边界。

07 / PROOF

证明“更像本人、更快发稿”

不新增人工打分负担；从真实发布动作自动获得质量证据。

NORTH STAR

连续真实项目中的本人感与发稿效率

每个项目只记一次，3 个项目形成方向判断，5 个项目冻结一轮观察。

01重生成次数

是否需要反复抽卡才能得到可用稿。

02编辑距离

最后一版 AI 稿到最终发布稿改了多少。

03创作耗时

首次生成开始到正式发布的真实时间。

04最终采用

直接、小改、大改采用，或无 AI 基线。

编辑距离中位数≤ 20%
平均重生成≤ 1.5 次
手动字数契约100%
生成可用引文100% 过质量门
08 / ROADMAP

下一阶段只推进能证明核心价值的事

路线从生成可靠性开始，经过个人反馈闭环和发布表达系统，最后才进入有限线上化。

P0NOW

生成质量与可靠性基线

建立“回忆”等真实项目回归样例；统一错误码、超时、检查点恢复、字数与书库质量检查。

  • 5 个真实项目无数据丢失
  • 失败可解释、可恢复
  • 成功稿满足硬契约
P1NEXT

无负担个人反馈闭环

把发布结果与 Skill 版本关联，聚合重生成、编辑距离、耗时和采用情况，不让用户填额外表单。

  • v2.1 / v2.2 真实项目对照
  • 高频人工修改归因
  • 候选规则由用户发布
P1NEXT

发布表达系统

把抖音发布适配做成可选择面板，建立栏目级封面预设，并打通项目、发布稿、封面和日记。

  • 正文到发布不超过 3 个主动作
  • 栏目视觉稳定复现
  • 资产可追溯
P2LATER

私密分享与有限线上化

先支持邀请制和只读展示，再考虑公共产品；补齐鉴权、Secret 托管、数据隔离、备份和用量保护。

  • 局部好友授权访问
  • 私人数据不可见
  • 不提前做公共 SaaS
09 / BOUNDARIES

克制，才让 Personal Agent 成立

边界不是缺少功能，而是防止产品偏离一个人的真实创作问题。

IN SCOPE

当前必须做好

  • 像创作者本人的完整 Vlog 文案
  • 稳定素材、生成、编辑和发布链路
  • 本地直引和对话记忆
  • 封面与真实作品资产
  • 可回退的个人 Skill 版本
NOT NOW

当前明确不做

  • 多人协作与商业化后台
  • 模板市场与公开社区
  • 自动发布和视频成片
  • 书籍全文托管
  • 无授权的公共数字分身
